# Seed witness contract

This companion to the [reading contract](contract.md) specifies derivations for the M06 bundle `seed-witness-v1.1`. The stage 1 reading contract, ontology and reconciled fixture bytes retain their separate digests. The following clauses correspond to ClaudeOracle's [15 questions](../reports/oracle_underspecified_v1.md).

1. **Identifiers.** The complete expanded inventory is available with `python3 -m src.reference --bundle`. Each entry has a stable ASCII ID, recipe ID, surface, ground category and cost. Specializations carry deterministic dot-separated suffixes for their choices. The two binary rule IDs are `seed.fa` and `seed.ba`.
   The article entries `det.a` and `det.an` both use recipe `det`, category `(NP[existential]/N)` and cost 0. The inventory's `next_nouns` lists the allowed immediately following normalized tokens for each of those two entries. Check this condition when anchoring the lexical edge, before counting it against the edge budget. A wrong article makes the sentence unlicensed (`no_root` in exact mode). Both articles use the ordinary determiner–noun application key.
2. **Shape.** Names and nouns each consume one token. A determiner first applies to N. A transitive first applies to its object. Control combines as `((verb recipient) (to bare-simple-VP))`, then takes its subject. Adverbs attach to the completed simple VP before closure. The auxiliary is one two-token lexical edge; the sentence-initial *not every* macro is another, applying first to N and then to a finite positive VP. Root semantic closure adds no chart edge or key.
3. **Instantiated categories.** Use the literal atom spelling in the inventory, including case and comma-separated finite features. Spell every slash node as `(result/argument)` or `(result\argument)`, including the outermost parentheses. Expand VP abbreviations. Emit no spaces. For example a result can be `(S[fin,simple,quick]\NP[universal])`. See the [guard definitions](dsl.md).
4. **Scope selection.** The transitive's lexical entry fixes its scope recipe, argument kinds and cost. Right and left application subsequently match those ground kinds. Other public recipes have one order.
5. **Rule recipes.** Both binary application edges use recipe ID `apply`. Surface order fixes the order of children in the key, including backward application.
6. **Costs.** Every transitive lexical occurrence, matrix or embedded, costs 10 in both orders. All other entries and binary edges cost zero. Equal-cost witnesses are then ordered by the count of object-wide uses and by structural key.
7. **Guard failure.** The bundle omits the object-wide specialization for two universals or two existentials. Only an edge belonging to a complete root derivation contributes a witness. A Unit controller or the Unit supplied by the auxiliary licenses both transitive recipes.
8. **Multiplicity.** Report every distinct complete root witness, globally sorted by the contract's ranking tuple. Each record has the reading it supports. The first witness for a given reading is its best. The separate canonical reading array is deduplicated and sorted by ASCII bytes.
9. **Key comparison.** Use the two tuple layouts in the reading contract. Compare integer fields numerically, ASCII fields by unsigned bytes, and ordered child-key sequences lexicographically. The leading 0 or 1 discriminates lexical and rule tuples before later fields are compared. JSON arrays encode these tuples on output; the JSON text itself is never the sort key.
10. **Overflow.** Lexical, rule and accumulated witness costs use signed 64-bit integers. Check every sum; overflow yields `error/abstain` with code `cost_overflow`.
11. **Budget.** Exact mode has no edge cap by default. The optional nonnegative integer `max_edges` limits distinct lexical and binary edges inserted across the sentence, including edges outside a root. A duplicate consumes no budget. The first would-be insertion above the cap yields `truncated/abstain`, code `edge_budget`, with empty result arrays. Malformed budgets yield `invalid_request`.
12. **Extra meanings.** Three or more distinct complete readings yield `error/abstain` with code `reading_count`. Preserve the full readings and ranked witnesses for diagnosis.
13. **Diagnostics.** Success has the empty diagnostic code. Exhaustive lexical or syntactic failure uses `empty_input`, `invalid_token`, `unknown_token` or `no_root`. Invalid requests, arithmetic overflow, incomplete search and extra readings use the codes above. An inconsistent typed engine result uses `engine_error`. Human-readable explanations in the original fixtures remain historical annotations.
14. **Tokens.** Return all normalized tokens even on lexical failure. Scan left to right and report the first offending token and its zero-based index; check its ASCII spelling before vocabulary membership. Well-formed known tokens without a licensed full-span finite root yield `no_root`. Once lexical validation succeeds, more than the seed maximum of 12 tokens proves there is no root before any edge is needed. A non-string sentence yields `invalid_request` and an empty token list.
15. **Empty input.** After the specified single-period removal and ASCII whitespace processing, zero tokens yields `no_parse/abstain` with `empty_input`, including for `.` or a space-padded period.

## Revision 2 · conformance for restricted bundles

This revision resolves the [second set of 15 questions](../reports/oracle_underspecified_v2.md). It applies to seed-1.0 and seed-1.1 with their own ontology and grammar digests.

1. **Edge identity.** Build every bottom-up span after validation. A node is the half-open start/end and ground category. A lexical insertion is identified by its node and entry ID. A binary insertion is identified by its parent, rule ID and both ordered child nodes. Distinct derivations inside either child share that binary edge. Distinct clone IDs consume separate lexical edges. Count edges outside complete roots, including on rootless inputs. A cap equal to the exact number permits completion.
2. **Precedence.** Validate sentence type and budget before tokenizing. Next come empty input, the first offending token, and the active length bound. Complete chart construction up to the edge budget before computing costs. Check cost overflow before producing ranked results. Thus a length rejection precedes even a zero edge budget, and a truncated chart yields no cost result.
3. **Tokens on an invalid request.** Return empty tokens, readings, ranked readings and witnesses, null minimum cost, and zero inserted nodes and edges.
4. **Budget type.** An omitted or null budget denotes exact mode. A nonnegative JSON integer is valid. Booleans, strings, negative integers and all floats (including 5.0) are invalid.
5. **Diagnostic fields.** The reference JSON has a string `diagnostic`, with top-level `token` and `token_index` only for a lexical failure on a particular token. For conformance, map these losslessly to the frozen cases' `diagnostic = {code[, token, index]}`. Compare both presence and value. The two encodings predate this revision.
6. **Vocabulary.** Take the union of surface tokens in the loaded entries, including multiword entries and clones. A known word can still fail to anchor in its context or with its lexical guard.
7. **Overflow scope.** Every licensed binary combination in the completed chart must have a signed 64-bit subtree cost, including combinations outside any full-span root. Add the costs of its immediate child witnesses in the specified tree, with zero rule cost. An out-of-range subtree is an error even if adding an ancestor would bring the total back into range. Any such witness invalidates the entire result, including competing safe witnesses. Return empty result arrays and null minimum cost. Checking minimum and maximum per packed node is sufficient.
8. **Negative costs.** The full signed 64-bit range is legal for lexical costs, including clone overrides. Both bounds are inclusive. An out-of-range lexical declaration is rejected at bundle construction.
9. **Witness fields.** Compare `cost`, `object_wide_uses`, `key` and `reading` for every witness, in order. The nested key already supplies the structural tree. The reference additionally emits the raw closure for inspection.
10. **Display order.** `ranked_readings` lists distinct readings in first-witness order. `readings` lists the same strings in canonical ASCII order. `min_cost` is the first witness's total cost, or null if there is none.
11. **Excess readings.** With three or more meanings, retain the full readings, ranked readings, ordered witnesses and minimum cost alongside `error/abstain/reading_count`.
12. **Binary costs.** Both published rules have implicit cost zero. The restricted-bundle format selects existing rules and inherits these costs.
13. **Roots.** The inventory publishes the five eligible categories: `S[fin,simple,plain]`, `S[fin,simple,quick]`, `S[fin,control]`, `S[fin,negative]` and `S[fin,not-every]`. A restriction can narrow this set, including to empty. A finite-looking category outside the active set cannot finish a witness.
14. **Engine failure.** A typed root term that fails closure or reading validation is an internal `error/abstain/engine_error`; discard partial outputs. The frozen set exercises publicly constructible outcomes. Deliberately broken internal state belongs in an implementation test.
15. **Tiny grammar input.** Pass a JSON object to `restrict_bundle(base, spec)` in `src.reference.restrictions`. Optional lists `entries`, `rules` and `roots` select distinct existing IDs or categories. An omitted list inherits the full base list and an empty list selects none. Optional `max_tokens` is an integer from zero through the base limit. Each optional `clones` record gives a fresh ASCII identifier `id` and a published `clone_of` from the base, even when that source is excluded from `entries`. The clone inherits meaning, recipe, ground category, cost, tokens and any immediate-follower guard. Optional `tokens` (nonempty lowercase ASCII word list) and `cost` override only those two fields. The restricted grammar recomputes its anchoring index, vocabulary and inventory digest. Pass the resulting bundle to the ordinary `parse(..., bundle=bundle)` entry point.

## Revision 3 · seed-1.1 article anchoring

This clarification resolves R1–R4 for the frozen seed-1.1 inventory. It preserves the reading contract, bundle digest and historical seed-1.0 behavior. [Article cases](../oracle/cases_witness_v11.json) · [Checked lexical entries](dsl.md)

1. **R1. Count an article edge only after its guard succeeds.** For a candidate lexical entry covering half-open span `[start,end)`, inspect normalized `tokens[end]`. If that position is absent or its token is outside that entry's `next_nouns`, skip this lexical alternative. It creates zero nodes, edges, witnesses or budget charges of its own. Other entries and spans still proceed. Thus in the restricted `articles` grammar, *a editor left* inserts the noun and verb edges only. Cap 2 yields `no_root`, cap 1 yields `edge_budget`. Whole-input lexical validation still precedes the chart: *an apple left* yields `unknown_token` in the full seed.
2. **R2. The seed uses an enumerated spelling policy.** At compilation, a normalized ontology noun starting with one of the five ASCII letters `aeiou` goes in the list for `det.an`. Each remaining noun goes in the list for `det.a`. The published lists contain six and fourteen noun surfaces respectively. The runtime tests membership in those lists. Pronunciation exceptions such as *hour* and *university* fall outside this vocabulary. Extending it to such cases requires an explicit lexical article assignment and a versioned inventory with contrast fixtures.
3. **R3. The guard belongs to lexical anchoring.** The seed bundle exports follower lists keyed by entry ID. The article checks the next surface token without consuming it or inspecting a chart item. If the article anchors, ordinary forward application must still find an N constituent for the determiner to form an NP. No extra field in a node or witness key, unary rule, or extra article cost is needed.
4. **R4. Clones inherit the source guard.** A restricted grammar copies the source entry's follower list under the clone's ID, including when its surface tokens or cost change. For a multi-token clone, test the token immediately after its entire span. A token or cost override cannot broaden the inherited list. A full and cloned `det.an` can therefore anchor as two distinct edges for *an editor left*, giving two structural witnesses and one reading; both guards fail for *an student left*. This instantiates revision 2 item 15.
